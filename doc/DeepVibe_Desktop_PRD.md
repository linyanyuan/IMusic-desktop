# DeepVibe 桌面端产品需求文档

## 1. 文档目的

本文档定义 DeepVibe 桌面端的产品目标、信息架构、核心流程和验收标准。桌面端应继承移动端已经验证的搜索、播放、歌单、曲库、歌词和账号同步逻辑，但不能只是把移动界面放大。桌面端的核心价值是让用户在更大的屏幕上同时完成发现音乐、管理队列、查看歌词和整理曲库。

## 2. 产品定位

DeepVibe Desktop 是一个面向个人听歌和轻量曲库管理的桌面音乐播放器。它以 Bilibili 播放源为主，结合 Meting/Karpov 等元数据来源，提供搜索、播放、歌单、歌词、播放队列和个人曲库同步能力。

推荐产品方向：Listening Studio。

桌面端应采用“常驻导航 + 中央工作区 + 右侧播放上下文 + 底部播放控制”的工作台布局。搜索结果、当前播放、队列、歌词、我喜欢和歌单管理可以并行呈现，减少移动端频繁页面跳转带来的上下文丢失。

## 3. 目标用户

1. 已经习惯 DeepVibe 移动端的用户，希望在电脑上继续使用同一套收藏和播放逻辑。
2. 经常搜索 Bilibili 音乐视频、合集、歌单并整理播放队列的用户。
3. 喜欢边工作边听歌，需要稳定播放、快捷键和小窗/迷你模式的用户。
4. 有轻量曲库管理需求的用户，例如收藏歌单、维护自建歌单、批量添加/删除歌曲。

## 4. 产品目标

1. 保持移动端搜索与播放策略一致：元数据优先，Bilibili 作为主要播放源，播放失败时有明确反馈。
2. 提供桌面优先的信息密度：搜索、队列、歌词、曲库不再互相遮挡。
3. 保持播放状态稳定：暂停后恢复不重新加载；切歌、队列、进度、播放模式行为一致。
4. 提升歌单管理效率：支持表格视图、批量选择、拖拽排序、右键菜单和快捷键。
5. 支持账号曲库同步：登录后同步我喜欢、自建歌单、主题设置和用户资料。

## 5. 非目标

1. 不做音乐版权平台替代品，不提供商业音乐分发能力。
2. 不做通用下载器，不导出平台音频文件。
3. 首版不做复杂社交、评论、多人歌单协作。
4. 首版不重建后端，只复用现有 API 与移动端服务逻辑。
5. 首版不追求专业 DJ、音频剪辑、频谱编辑等重型功能。

## 6. 信息架构

### 6.1 主导航

左侧常驻导航包含：

- 首页：推荐歌单、最近播放、快捷搜索入口。
- 搜索：歌曲、歌单、歌手/合集结果，支持分组与筛选。
- 我的音乐：我喜欢、自建歌单、历史播放、离线缓存状态。
- 设置：账号、主题、播放音质、更新检查、关于。

### 6.2 中央工作区

中央区域根据当前导航变化：

- 首页展示推荐内容和继续播放。
- 搜索展示结果列表与歌单卡片。
- 歌单详情展示歌曲表格、批量操作、播放全部和收藏。
- 我的音乐展示曲库表格和歌单管理。

### 6.3 右侧上下文栏

右侧栏常驻，包含：

- 当前播放封面与基础信息。
- 歌词/暂无歌词/歌词加载状态。
- 当前队列，可切换顺序、随机、单曲循环。
- 下一首播放优先队列。

### 6.4 底部播放栏

底部播放栏常驻，包含：

- 上一首、播放/暂停、下一首。
- 播放模式、音量、进度条、播放时间。
- 当前播放源标识，例如 B站播放、腾讯音乐元数据。
- 更多操作：添加到歌单、缓存状态、查看详情。

## 7. 核心功能需求

### 7.1 搜索

需求：

- 搜索框支持歌曲、歌手、专辑、Bilibili 视频/合集关键词。
- 结果区分：综合、单曲、歌单/合集、歌手/集合。
- 结果必须展示来源标签、标题、艺人/UP 主、时长、封面、播放源标签。
- 点击歌曲直接加入队列并播放。
- 点击歌单/合集进入详情页，加载歌曲列表。
- 支持搜索历史和清空历史。

验收：

- 输入关键词后 800ms 内优先展示可用结果，较慢元数据后续补齐。
- 搜索空字符串不发起请求。
- 失败时展示可重试状态，不清空已有播放。

### 7.2 播放

需求：

- 复用移动端播放逻辑：`MusicProvider.getPlayUrl` 获取播放地址，Bilibili 为主要播放源。
- 暂停后恢复必须从当前进度继续，不重新加载音源。
- 播放开始后记录最近播放。
- 支持上一首、下一首、顺序播放、随机播放、单曲循环。
- 支持优先下一首队列。
- 支持进度拖动和音量控制。

验收：

- 已加载音源恢复播放时只调用 resume，不重新 setUrl。
- 切歌时旧音频先暂停，再加载新音源。
- 播放失败恢复到上一首可播放状态并提示原因。

### 7.3 队列

需求：

- 右侧队列常驻展示当前播放列表。
- 当前歌曲高亮并显示动态播放状态。
- 支持点击队列歌曲立即播放。
- 支持移除歌曲、清空队列、拖拽排序。
- 支持“下一首播放”。

验收：

- 删除当前播放歌曲后自动切换到合理下一首。
- 随机模式下下一首播放优先于随机选择。

### 7.4 歌单与曲库

需求：

- 支持收藏远程歌单到我的音乐。
- 支持创建、删除、重命名自建歌单。
- 支持从搜索结果、最近播放、当前播放添加歌曲到歌单。
- 支持批量选择、批量添加、批量删除、批量缓存状态标记。
- 支持我喜欢的音乐。

验收：

- 自建歌单删除当前播放歌曲时，队列和当前播放状态同步更新。
- 收藏和喜欢的歌曲播放后会写回稳定播放元数据，例如 playbackId 和 lyrics。

### 7.5 歌词

需求：

- 优先使用歌曲已有歌词。
- 对 Bilibili 播放源尝试从字幕或匹配元数据歌词补齐。
- 歌词加载中、无歌词、加载失败有明确状态。
- 桌面端右侧栏默认展示歌词，支持放大专注模式。

验收：

- 歌词请求不阻塞播放。
- 歌词超时后显示暂无歌词，不无限加载。

### 7.6 账号与同步

需求：

- 支持注册、登录、登出。
- 登录后同步远端曲库：我喜欢、自建歌单、主题设置。
- 支持头像、昵称、头像文字更新。
- 未登录时保留本地基本体验。

验收：

- 未过期会话重启后自动恢复。
- 过期会话回到登录页并清理本地会话。

### 7.7 桌面专属能力

首版建议包含：

- 全局或应用内快捷键：空格播放/暂停，左右方向 seek，上下方向音量，Ctrl/Cmd+F 搜索。
- 可调整窗口尺寸，最小宽度建议 1024px。
- 右键菜单：歌曲、歌单、队列项。
- 迷你播放器模式：小窗展示封面、标题、播放控制。
- 系统媒体控制：系统托盘/媒体键集成，视平台能力实现。

## 8. 关键页面

### 8.1 首页

桌面首页不是营销页。首屏直接展示可操作内容：继续播放、搜索入口、热门歌单、最近播放。

### 8.2 搜索页

搜索页是桌面端核心工作台。左侧可保留筛选，中央结果表格，右侧队列/歌词不消失。

### 8.3 歌单详情页

采用表格和卡片混合：顶部展示歌单信息和主操作，下面展示歌曲表格。支持批量管理。

### 8.4 我的音乐页

以曲库管理为主，支持我喜欢、自建歌单、历史播放、离线缓存状态切换。

### 8.5 完整播放器/专注模式

作为可进入的沉浸状态，不替代主工作台。展示大封面、歌词、队列和播放控制。

## 9. 视觉方向

桌面端采用克制的“夜间监听工作台”风格：深色为主，局部高亮 cyan，使用高对比文字和清晰层级。避免大面积紫蓝渐变、装饰性光球、营销式 hero。界面应像专业播放器和轻量工作台，而不是宣传页。

布局原则：

- 卡片半径不超过 8px。
- 工具按钮优先图标化。
- 歌曲列表使用表格密度，不用大卡片堆满页面。
- 保持底部播放条稳定尺寸，不因歌词、封面或加载状态跳动。
- 文本不压缩、不溢出，长标题使用省略和 tooltip。

## 10. MVP 范围

P0：

- 登录/会话恢复。
- 首页推荐、最近播放。
- 搜索歌曲和歌单。
- 歌单详情、播放全部、收藏。
- 完整播放链路、队列、播放模式、进度、音量。
- 我喜欢、自建歌单、历史播放。
- 歌词状态展示。

P1：

- 右键菜单、快捷键、拖拽队列排序。
- 迷你播放器。
- 批量管理增强。
- 桌面端更新检查。

P2：

- 多窗口歌词、桌面歌词。
- 高级音频设备选择。
- 更完整的离线缓存能力。

## 11. 成功指标

- 搜索到播放的首次成功路径少于 3 次点击。
- 暂停恢复不重载音源。
- 热门歌单加载更多不跳动。
- 桌面端 1024px 到 1920px 宽度下核心布局稳定。
- 关键回归测试覆盖搜索、播放、队列、歌单、曲库同步。
