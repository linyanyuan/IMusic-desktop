# 搜索、播放与歌单响应优化变更说明

## 本次改动

### 1. 点击歌曲立即响应

- 点击搜索结果或歌单详情中的歌曲后，立即停止当前歌曲。
- 新歌曲立即进入 `loading` 状态，不再等播放地址、缓存和字幕全部完成后才更新界面。
- 播放请求增加序号保护：连续点击多首歌曲时，只允许最后一次点击更新播放器，旧请求完成后不会把新歌曲覆盖掉。
- 歌词和 B 站字幕移出播放启动关键路径，在音频开始播放后异步加载。

说明：Windows 首次播放带请求头的音频时，仍会按原方案完整缓存到本地，因此网络慢或文件较大时仍需等待，但点击后会立即停止旧歌并显示加载状态。

### 2. 播放进度条加载动画

- 当前歌曲为 `loading` 时，底部进度条显示循环移动的不确定进度动画。
- 加载期间禁用点击和拖动跳转。
- 播放或暂停时恢复普通进度条；播放失败、播放完成或没有歌曲时显示静态空轨道。

### 3. 搜索歌单立即展示

- 搜索接口返回基础结果后立即显示歌单，不再串行等待每个歌单的分P信息。
- 后台最多并发查询 4 个歌单摘要，并逐行更新歌曲数量和集合类型。
- 多分P歌单显示“X 首歌曲 · 分P合集”。
- 单个长音频合集显示“歌曲集合”和时长；可从标题估算数量时同时显示歌曲数。
- 离开搜索页再返回时，未完成的摘要补全会继续执行。
- 旧搜索请求的结果不能覆盖用户后续发起的新搜索。

### 4. 移除艺人搜索 Tab

搜索页现在只保留：

- 综合
- 歌曲
- 歌单

原艺人 Tab 没有可用数据来源，已从界面和搜索分支中移除。

### 5. 加入歌单立即反馈

- 右键选择目标歌单后，歌曲立即加入本地列表并显示处理中反馈。
- 后台只补充稳定播放标识，不再为收藏操作请求真实音频地址、字幕或下载音频。
- 远端曲库保存改为串行 mutation 队列，避免多个收藏、喜欢或删除操作互相覆盖。
- 保存失败时只回滚本次操作，不恢复整份旧歌单快照。
- 登录账号切换后，旧账号尚未完成的加载、解析和保存请求不能写入新账号状态。

### 6. 统一 B 站歌曲身份

- `bilibili:BVxxx` 与 `bilibili:BVxxx:p1` 视为同一首歌曲。
- 搜索页、歌单详情、喜欢列表和歌词窗口共用同一身份判断。
- 避免同一首 B 站歌曲被重复加入歌单或重复喜欢。

## 用户可见效果

1. 点击歌曲后旧歌曲立即停止，底部进度条马上进入加载动画。
2. 歌单搜索结果先出现，歌曲数量随后自动补全，页面不会长时间空白等待。
3. 加入歌单后界面立即更新，不再等待播放地址解析完成。
4. 快速连续点击歌曲、切换账号或并发修改歌单时，旧异步请求不会覆盖较新的操作。
